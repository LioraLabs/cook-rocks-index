cook's blessed modules

This is the LuaRocks index cook installs modules from. Pin a version under [modules] in cook.toml, add use cook_cc to your Cookfile, and cook fetches the rock itself. Every module contributes ordinary units to the same graph and the same cache.

cook_cc

Cook C-family (C + C++) native build module

0.20.0: probe declarations drop `inputs.env`, which CS-0244 removed from cook and which cook now rejects outright at register phase. Every project on 0.19.x fails at `cook menu` against a cook carrying CS-0244, because `cc:linker-search-dirs` declares LIBRARY_PATH before anything else runs.

# cook.toml
[modules]
cook_cc = "0.20.0-1"
needs lua-cjson ~> 2.1, lpeg ~> 1.0 docs source

cook_dotnet

Fresh, cacheable .NET builds for Cook

0.5.0 adds selected build, run, and native test workflows, automatic recovery of missing build state, and reference-assembly cutoffs that preserve current runtime bytes. Generic Cook tests include native .NET tests and propagate their failures. Batched SDK discovery and sealed toolchain fingerprints reduce repeated work; native include roots avoid unrelated frontend membership changes, with conservative fallback for authored and package-supplied dynamic input rules.

[modules]
cook_dotnet = "0.5.0-1"

cook_pnpm

Cook pnpm blessed module with namespaced workspace tasks

Blessed Cook module for pnpm-driven JS/TS projects. One cook_pnpm.workspace{} call parses pnpm-workspace.yaml + each package.json, registers toolchain + install probes (keyed on the pnpm-lock.yaml hash), mints one pnpm:<dir>:<task> recipe per (package, task) in topological order, auto-mints conventional checks, and mints the install stage.

# cook.toml
[modules]
cook_pnpm = "0.11.0-1"
needs lua-cjson ~> 2.1 docs source
